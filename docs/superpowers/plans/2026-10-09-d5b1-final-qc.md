# D5B.1 Final QC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Native is recommended for this tightly coupled, small backend feature; the user must approve this plan and confirm the execution method before implementation.

**Goal:** Analisar masters existentes por variante e publicar relatórios técnicos imutáveis, sem regenerar mídia nem aprovar vídeos automaticamente.

**Architecture:** Um serviço síncrono no pacote editing seleciona masters históricos por renderKey e valida sua identidade com o mesmo helper usado pela API. Reutiliza checks de mídia e ASS, mede áudio com FFmpeg e publica JSON vinculado ao master/receipt/política/runtime. CLI expõe execução e consulta; nenhuma nova integração HTTP, Job ou UI.

**Tech Stack:** Python 3.11, Pydantic 2, Typer, pytest, FFmpeg/ffprobe/libass e stdlib já presentes.

**Spec:** `docs/superpowers/specs/2026-10-09-d5b1-final-qc-design.md`, aprovada pelo usuário em 2026-10-09; commit `968f33d`. Baseline de produto `30b799c`.

## Global Constraints

- `schemaVersion: "1.0"`; aliases camelCase e `EditingModel`, sem paths arbitrários na request.
- Política `final-qc-v1`: loudness abaixo de −30 LUFS bloqueia; true peak maior ou igual a 0 dBTP bloqueia. Limites internos iniciais, não requisito de plataforma.
- Medir `input_i`/`input_tp`, não áudio normalizado. JSON nunca contém NaN/Infinity.
- `passed` não é aprovado: `humanReviewRequired: true`; clareza de voz/distorção exige escuta humana em D5B.2.
- Sem UI, HTTP, Jobs, worker, SQL/migration, dependências novas, providers, OCR/ASR ou correção/encoding de MP4.
- Sem chamada a render/dry-run para localizar masters; receipt produtor pode ter planHash diferente do consumidor.
- Persistir apenas relatórios completos passed/blocked; error não cacheado; sem retry automático nem sobrescrita.
- Variantes sequenciais; identidade/global admission antes de writes; erro de uma variante não impede as demais.
- Preservar APIs/CLI/schemas de render, AGENTS.md, sources/ e alterações alheias. Flow continua pausado.
- Shell usa `rtk`; edição usa apply_patch; gerar schemas pelo exporter existente é permitido.
- No início da execução, usar using-git-worktrees para isolar a implementação a partir do commit documental aprovado; não reutilizar o worktree antigo D5A.2 nem sua pasta temporária.
- Não merge/push neste plano sem pedido posterior. Evidência local/CI não significa PROVIDER_VERIFIED.

## Review Focus

1. Runtime de render antigo, diferente do atual: selecionar o master pedido sem inferir um renderKey novo (Task 4).
2. Report passed com status/checks adulterados, mesmo que seus hashes de mídia estejam corretos: rejeitar a consulta/reutilização (Tasks 1/4).
3. Texto desabilitado e ausência de fontes/timing: não exigir assets opcionais nem chamar libass para blocos inexistentes (Tasks 3/4).
4. Runtime indisponível para todas as variantes: retornar batch error completo na ordem pedida, sem reports parciais (Task 4).
5. Arquivo substituído depois de aberto: API serve apenas o handle que validou, sem reabrir pelo path (Task 2).

### Task 1: Contratos e schemas de QC

**Interfaces:**
- `QcTarget(EditingModel)`: output_variant_id: Identifier, render_key: Sha; `QcRequest`: schema_version, campaign_id/video_id: Identifier, plan_hash: Sha, outputs: list[QcTarget] não vazia e IDs únicos.
- `QcPolicy`: version literal `final-qc-v1`, min_loudness_lufs literal -30.0, max_true_peak_dbtp literal 0.0, comparison semantics fixas; sem overrides na request. `QC_VERSION="1.0"`.
- `QcFinding`: code/field/message sanitizados; `QcCheck`: name literal integrity/audio/text, status passed/blocked/not_applicable/skipped, findings. `QcAudio`: integrated_loudness_lufs/true_peak_dbtp: float finito | None.
- `QcReport`: campos da spec; probe: MediaProbe | None (probe indisponível em blocked por mídia inválida); checks: lista dos três checks; audio: QcAudio | None; status passed/blocked; human_review_required literal True; relative master_path e size_bytes, receipt_sha256, runtime: RenderRuntime, policy: QcPolicy, policy_hash/qc_key: Sha, qc_version literal 1.0.
- `QcOutputResult`: output_variant_id/render_key, status passed/blocked/error, reused: bool, qc_key/path para report válido ou error: QcFinding, mutuamente exclusivos. `QcBatchResult`: contexto da request, outputs na ordem e computed has_failures.
- `qc_key(*, plan_hash: str, output_variant_id: str, render_key: str, master_sha256: str, receipt_sha256: str, qc_version: str, policy_hash: str, runtime_fingerprint: str) -> str`, via content_hash.
- `validate_qc_report(report: QcReport) -> None`: recalcula identidade/policy hash e coerência dos checks/metrics/status. `export_qc_schemas(output_dir: Path) -> tuple[Path, ...]`: request/report validation, batch serialization; chamado pelo entrypoint existente.
