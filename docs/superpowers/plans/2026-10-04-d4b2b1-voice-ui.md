# D4B.2b.1 Voice UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Operar orçamento inicial, geração/importação e revisão de Voice Masters pela campanha na UI local, sem CLI/JSON manual nem provider pago nos testes.

**Architecture:** Formulários React consomem a API e os serviços/workers existentes. A única nova ação de backend configura o orçamento inicial no JSON de campanha, sem Job ou migration. IDs aceitos são acompanhados por GET; requests incertas nunca recebem retry automático pela UI.

**Tech Stack:** Python 3.11, Pydantic, SQLAlchemy/SQLite, FastAPI, React/TypeScript/Vite, pytest, Vitest/Testing Library e Playwright já instalados.

**Spec:** `docs/superpowers/specs/2026-10-04-d4b2b1-voice-ui-design.md` (aprovada).

## Global Constraints

- "Uso local e pessoal, delivery-first." Sem HeyGen nesta entrega.
- "Ouvir o WAV fora da UI foi explicitamente aprovado para este recorte."
- "A headline não entra no texto falado." Fixar versão aprovada na request.
- "Sem novas dependências ou migrations." Sem player/upload/catálogo/editor JSON.
- Orçamento: código de três letras ASCII maiúsculas, inteiro positivo em centavos, nunca float/boolean. Não alterar configuração já definida.
- "A gravação não autoriza nenhuma geração." Autorização de gasto e review têm confirmações distintas.
- "Cada start é explícito e segue o escopo de campanha/tipo." Não restringir falsamente ao Job do formulário.
- "Preservar políticas de retry/checkpoint do engine atual." Sem POST retry, auto-start ou auto-resume pela UI.
- "Original preservado; pipeline mantém WAV mono/48 kHz/24-bit, normalização e trim de silêncio nas duas bordas."
- "Não fornecer transcript manual substituto." Exceção de review somente nas condições do serviço.
- "Isso estabelece somente LOCAL_VERIFIED, não novo PROVIDER_VERIFIED."
- Não alterar AGENTS.md, sources, lockfiles ou processamento de áudio. Prefixar comandos shell com `rtk`; usar `rtk proxy` para saída sem filtro quando necessário.

## Review Focus

1. Dois saves iniciais concorrentes com valores distintos não podem sobrescrever orçamento: transação serializa decisão/gravação (Task 1).
2. JSON legado parcialmente preenchido, boolean ou número fora da representação segura do browser não deve virar teto arredondado: GET distingue invalid e frontend falha fechado (Tasks 1–2).
3. POST persistido com resposta perdida não prova inexistência nem identidade por coincidência de copy/provider: só GET pós-assentamento, sem segundo POST (Tasks 2–5).
4. Wrapper de import concluído com filho falho ou worker idle não equivale a áudio aprovado: exibir fases/IDs reais e preservar bloqueios (Tasks 3–5).
5. Mudança de campanha/copy/voz durante requests e DTO nulo/incompleto não pode aplicar aprovação antiga ou apagar último snapshot válido (Tasks 2–4).
