# D4B.2b.2 HeyGen UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preparar assets, planejar/autorizar batch HeyGen, acompanhar MP4s e reconciliar Jobs bloqueados pela UI local, sem CLI/JSON manual nesses comandos.

**Architecture:** Formulários React na campanha consomem as operações e workers existentes. Um cliente focado valida DTOs de HeyGen; estado de formulário/monitoramento permanece no componente, sem engine ou abstração genérica nova. O backend continua autoritativo para material, conta, reservas e reconciliação.

**Tech Stack:** Python 3.11, FastAPI/Pydantic, SQLite/SQLAlchemy, React/TypeScript/Vite, Vitest/Testing Library, pytest/Playwright existentes.

**Spec:** `docs/superpowers/specs/2026-10-05-d4b2b2-heygen-ui-design.md` (aprovada em 2026-10-05).

## Global Constraints

- "Uso local e pessoal, delivery-first." Batch inclui todas as cenas; sem seletor parcial.
- "Reutilizar as imagens aprovadas e o mesmo WAV processado/aprovado; não gerar voz ou imagens neste fluxo."
- Defaults fixos: image, provider_default, 9:16, 1080p, MP4, cover, medium, motionPrompt null; concurrency 2, pollInitialSeconds 10, pollMaxSeconds 60, pollTimeoutSeconds 1800, schemaVersion 1.
- "limite total de renders reservados da campanha": `maxPaidRenders` inteiro positivo seguro no browser, incluindo reservas históricas; não moeda/centavos/saldo.
- "Plano é informativo, não um snapshot imutável que a API aceita como token." Backend recalcula na submissão.
- "Wrapper concluído não equivale a filho concluído." Worker idle não prova sucesso.
- "Não acrescentar sleeps arbitrários na UI." Pacing/polling do engine preservados.
- "Reload não dispara mutações." Starts explícitos; stop não cancela chamada paga nem reembolsa créditos.
- "OAuth permanece no mecanismo existente da CLI/runtime." Nenhum token/URL assinada na UI.
- Sem dependências, migrations, player/upload, wizard/editor avançado, force regeneration ou POST retry automático.
- Não alterar AGENTS.md, sources, áudio, lockfiles, provider ou políticas de engine. Mudança de contrato público exige nova revisão de escopo.
- "Fake/local estabelece LOCAL_VERIFIED, nunca novo PROVIDER_VERIFIED." Nenhum crédito/canary neste plano; merge/push exigem autorização posterior.
- Todos os comandos shell começam com `rtk`; edições usam apply_patch. Referências de arquivos neste documento são relativas à raiz do repositório.

## Review Focus

1. POST persistido com resposta perdida: intenção unknown e inspeção GET, sem segundo POST ou identificação por coincidência (Tasks 1–3, 5).
2. GET completed com filho ainda failed/blocked, ou GET tardio depois de fase 2: preservar IDs/fase comprovados, nunca regressar para start de fase 1 (Tasks 1, 5).
3. Histórico com FAILED/reconciliation_required ainda ocupa reservas; limite inadequado não pode parecer saldo livre (Tasks 2, 5).
4. Resposta com mesma shape mas campanha/tipo/Job errado, IDs repetidos ou cena estrangeira: stale, último snapshot e autorização preservados com bloqueio (Tasks 1–4).
5. Mudança de campanha/material durante POST/GET e aceitação de outra ação: resposta antiga não atua na campanha nova nem limpa outro draft (Tasks 1–3).

- Create `web/src/HeyGenPanel.tsx` e `.test.tsx`: preparação, planejamento/submissão, monitoramento e subform de reconciliação.
- Modify `web/src/CampaignPanel.tsx` e `.test.tsx`: montar o painel na seção HeyGen e validar coleções/contexto na origem.
- Modify `web/src/api.test.ts`, `web/src/VoicePanel.test.tsx`, `web/src/WorkerControls.test.tsx` somente se fixtures compartilhadas de renders forem afetadas; manter DTOs completos.
- Modify `web/src/styles.css` somente se teste de largura estreita provar overflow; usar regra scoped, não ocultar overflow global.
- Create `tests/test_web_heygen_e2e.py`; modify `tests/web_panel_support.py` para injetar provider fake por fixture, preservando o default atual dos demais testes. Download HTTP fake é injetado no handler real somente pelo teste novo.
- Modify `.github/workflows/verify.yml`, README e os três documentos de produto na entrega final.

Reusar `read<T>(path, signal, accepts?)`, `post<T>(path, body)`, `campaignPath(id, suffix)`, `usePolling<T>(key, load, intervalMs)`, `RemoteState<T>`, `useUnsavedChanges(boolean)` e WorkerControls. Não criar outro transporte/runner/hook genérico.

`HeyGenPanelProps`: campaignId: string; detail: RemoteState<CampaignDetail>; status: RemoteState<CampaignStatus>; images: RemoteState<Items<SceneImages>>; voices: RemoteState<Items<VoiceSummary>>; jobs: RemoteState<Items<JobSummary>>; renders: RemoteState<Items<RenderSummary>>. Dados permanecem nos hooks do painel pai; wrappers têm polling próprio por Job aceito. `HeyGenPanel(props: HeyGenPanelProps): JSX.Element` remonta por campaignId.

No cliente, `HeyGenOperationKind` = heygen_assets | heygen_video_plan | heygen_video_submit | heygen_reconcile. `HeyGenSubmission` contém jobId, campaignId, operation. `HeyGenOperationView` adiciona status, errorCode e result discriminado conforme `api/action_contracts.py`: assets(uploadCount, reusedCount, jobId nullable), plan(newCount, reusedCount, reservedCount, maxPaidRenders, totalAudioSeconds, sceneVariantIds), submit(renders), reconcile(render). Status do wrapper: queued, running, completed, failed, blocked, retry_scheduled, cancelled. Manter os nomes camelCase reais, não inventar requestId no GET.

`HEYGEN_DEFAULT_CONFIG` contém exatamente os defaults da seção Global Constraints. Guards públicos `heygenSubmission(value: unknown): value is HeyGenSubmission` e `heygenOperationView(value: unknown): value is HeyGenOperationView`. Validar status enum, contagens seguras não negativas, limite positivo, segundos finitos, IDs não vazios/únicos e discriminador coerente; completed requer result. Guards de forma não provam contexto: conferir campanha, operation e jobId solicitado no consumidor.
